# V29 - Remember together without sharing everything

Status: technical rehearsal brief for Cairnkeep 2.27.0 operations and guided
onboarding to the opt-in preview introduced in 2.25.0. Not a recorded or
independently rehearsed lesson.
Target: 10–12 minutes, experienced-developer audience. Describe a released
experimental preview, not a generally production-admitted team service.
Use the [isolated pilot guide](../../team-pilot.md) for a separately authorized
native-harness trial, not as authorization to record private review or credentials.

## 0:00–1:30 — Continuity is the goal

“The useful part is not winning a one-shot puzzle. It is continuing tomorrow,
in another harness, without explaining the same project decision again.”
Pause, then introduce the new boundary: your private memory is not a team bucket.
Show the proposal/review/revision lifecycle, one stage at a time.

## 1:30–3:30 — Deliberately separate identities

Use a disposable source checkout and only synthetic fixtures. Show
`bin/cairn team --help` and the default-off failure. Read the roles in
`docs/team.md`; highlight that a reviewer token is human-only and is never
handed to the agent. Briefly show initialization/membership command forms,
with no token contents on screen. The server is loopback-only.
Use the [role-based handoff](../../team-onboarding.md) connection card to show
which steps belong to the operator, reader and human reviewer. Run its actual
reader check in the disposable lab; never film a credential or replace the
personal memory entry. Keep a pause on the pending deployment decisions.

## 3:30–6:00 — Make the boundary visible

Type the six L29 control commands at human speed; use completion where useful.
Split the terminal: immutable selected proposal on one side, human review and
approved retrieval on the other. Use the actual fixture results rather than
fabricating a transcript. Pause on denied workload/self-review and the stale
digest/base controls. Explain that confirming a hash does not prove human consent.

## 6:00–8:00 — Change clients, not authority

Run `smoke-team-mcp.mjs` separately and inspect its maintained fixture: two
actual stdio clients, different cwd, same approved project decision. Zoom into
project provenance, then contrast an unrelated project denial and live token
revocation. Do not claim the test launched every named commercial harness.
Show `cairn team member remove SUBJECT --project ID --data DIR` as the explicit
project-offboarding command. Pause on the connected client's denial; explain
that removing one project membership does not revoke all of that person's tokens.
An additional MCP entry is opt-in; existing memory servers are not replaced.

## 8:00–10:00 — Recovery with a catch

Run `smoke-team-restore.mjs` and `smoke-team-cli.mjs`. Leave a two-second pause
on “restored credentials revoked”: copying a backup must not silently restore
access. Show fresh-only restore, no-overwrite and uninstall-retention controls.
Explain that logical deletion is not secure disk erasure or backup deletion.

With a matching 2.26.0-or-newer client and team API, insert a short dynamic client segment:
open the harness checkboxes in `team connect`, pause on the no-write plan and
read-only default, then explicitly apply in a disposable project. Keep the
personal MCP entry visible beside the new team entry. Run `team doctor --client`
and zoom into expiry/project/roles, never the token file or original-config
backup. Switch folders, show the pinned project, then plan/apply disconnect.
Explain that disconnect is not revocation and running sessions need a restart.
Use the maintained `smoke-team-onboarding.mjs` results for interruption/drift
controls, not a fabricated typing transcript. The automated human-class policy
fixture is not actual human consent; no independent-human trial is claimed.
Do not record this addition against a 2.25-only client/API; follow the version
note in the onboarding guide and verify the published package before recording.

## 10:00–11:30 — Honest closing

End on the admission checklist in `docs/team.md`, not a production deployment.
Distinguish completed regression controls, the internal governed review and
the approved isolated native pilot from independent production review and a
deployment-specific real-data pilot. Do not imply two independent human testers.
Explain that personal-memory embeddings/reranking never process team search.
Distinguish the JSON API/local stdio bridge from OAuth
remote MCP. Call out OIDC, team packs and multi-organization tenancy as deferred.

[operations recipe](../../team-operations.md). Show the capacity counters,
optional page envelope and stale-cursor refusal, then a stopped disposable
service, read-only backup, audit export, no-write archive plan and exact apply.
Pause on “older server binaries cannot reopen v2”; keep all backups and tokens
off screen. Show the synthetic endurance counts without claiming real human
consent, native-harness UI coverage or a quality benchmark. Do not record these
commands against an older CLI/API; this remains a rehearsal brief.

Use legible real terminals, short scene changes, natural pauses and emphasis
around each changed authority boundary. Keep credentials, personal memory,
source excerpts from private projects and raw snapshot text off screen.
Do not enroll a real user, deploy, purchase services or mutate live MCP config
to produce the video. This brief does not imply a video has been recorded.
